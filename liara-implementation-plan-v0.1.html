هدف این سند: تبدیل دامنه کامل PRD به ترتیب ساخت، معماری اجرایی، رجیستری قابلیت، و معیار Done هر فاز — بدون کوچک‌کردن دامنه محصول.

دامنه PRD کامل می‌ماند. فازها فقط اولویت تحویل هستند. قابلیت ساخته‌نشده یا آزموده‌نشده باید در رجیستری disabled یا documented بماند، نه «کامل» اعلام شود.

۱. هدف و قواعد غیرقابل مذاکره

حلقه محصول (از PRD):

هدف ← شاهد ← طرح ← اجازه ← اقدام ← سنجش ← بازیابی / ادامه

قاعدهمعنی عملی
کنترل اجازههیچ نوشتن حساسی بدون طرح مشخص + اجازه معتبر
رازتوکن و credential به مدل، لاگ محصول، گزارش، URL و telemetry نرود
پاسخ نامعلومبعد از timeout نوشتن، فقط تطبیق خواندنی؛ بدون retry کور
رجیستری قابلیتمستند ≠ آزموده ≠ فعال برای کاربر
کانال اصلیوب فارسی / RTL؛ CLI/MCP اختیاری‌اند
نتیجه واقعیHTTP 200 یا پذیرش درخواست کافی نیست؛ نسخه + کارکرد

۶. الگوریتم عملیات ماندگار

  1. اعتبارسنجی مقصد، نقش، اجازه، hash طرح، سقف هزینه — بدون نوشتن در صورت شکست.
  2. ثبت قصد و fingerprint قبل از HTTP.
  3. قفل منبع متأثر.
  4. فراخوانی ارائه‌دهنده.
  5. checkpoint فوری شناسه provider.
  6. timeout → unknown → فقط reconcile خواندنی.
  7. Verification با معیار از پیش ثبت‌شده.
  8. شکست میانی: منابع باقی در Case؛ حذف جبرانی فقط با اجازه.

۱۵. تعریف تکمیل نسبت به PRD

این طرح وقتی هم‌راستا با محصول کامل است که چک‌لیست بخش ۱۷ PRD و سناریوهای L-AC01 تا L-AC50 با شواهد پاس شوند. تکمیل یک فاز به معنی تکمیل کل محصول نیست.

مرجع دامنه همیشه liara-prd-v0.3.md است. در تعارض رفتار، PRD اولویت دارد مگر تصمیم محصولی نسخه‌دار جایگزین شود.
